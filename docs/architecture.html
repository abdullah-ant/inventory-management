System Architecture

Factory Inventory Management System

A full-stack demo for tracking inventory, orders, demand, and spending across factory warehouses. A Vue 3 single-page app talks to a FastAPI service that serves filtered, in-memory mock data — no database.

Vue 3 + Vite FastAPI + Pydantic In-memory JSON i18n (EN / JA)

03 — Request lifecycle

Data Flow

How a filter change travels from a click in the UI to validated JSON on screen. The four global filters — Time Period, Warehouse, Category, Order Status — drive nearly every view.

1

User adjusts a filter

The global FilterBar updates shared singleton refs in useFilters.js — selectedPeriod, selectedLocation, selectedCategory, selectedStatus — so every view sees the same filter state.

2

View builds the filter set & calls the API client

A view calls getCurrentFilters() to assemble a filter object (mapping period → month), then invokes a method on api.js.

3

Axios issues the HTTP request

api.js serializes filters into URLSearchParams, dropping any value equal to 'all', and sends an Axios GET to http://localhost:8001/api/….

4

FastAPI filters in-memory data

The endpoint runs apply_filters() (warehouse / category / status) and filter_by_month() (direct month or Q1–Q4 quarter mapping) over the in-memory lists — pure Python list comprehensions, no database.

5

Pydantic validates & serializes the response

The result is shaped by a response_model (e.g. List[InventoryItem]), guaranteeing a consistent JSON contract back to the client.

6

Vue stores raw data & derives the view

The view saves the response into reactive refs, then computed properties derive sorted lists, totals, and chart series — which Vue renders reactively as tables and SVG charts.

04 — Contract

API Endpoints

All read endpoints under /api. Filters are optional query params; a value of all (or omission) means "no filter".

MethodPathPurposeFilters
GET/api/inventoryList inventory itemswarehouse, category
GET/api/inventory/{id}Single inventory itemnone
GET/api/ordersList orderswarehouse, category, status, month
GET/api/orders/{id}Single ordernone
GET/api/demandDemand forecastsnone
GET/api/backlogBacklog items (+ purchase-order flag)none
GET/api/dashboard/summaryAggregated KPI summarywarehouse, category, status, month
GET/api/spending/summarySpending totalsnone
GET/api/spending/monthlyMonthly spending breakdownnone
GET/api/spending/categoriesSpending by categorynone
GET/api/spending/transactionsRecent transactionsnone
GET/api/reports/quarterlyQuarterly performance reportnone

Note: the frontend api.js also references task and purchase-order write endpoints (/api/tasks, /api/purchase-orders) that are in-progress on this branch and not yet defined in main.py.
